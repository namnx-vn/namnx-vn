## 🏗️ Architecture

I approach frontend architecture around **boundaries, contracts, ownership,
and independent evolution**.

```text
                         ┌──────────────────────────┐
                         │       User / Browser     │
                         └────────────┬─────────────┘
                                      │
                         ┌────────────▼─────────────┐
                         │       Host Application   │
                         │   Routing / Auth / Shell │
                         └────────────┬─────────────┘
                                      │
              ┌───────────────────────┼───────────────────────┐
              │                       │                       │
      ┌───────▼────────┐     ┌────────▼───────┐      ┌──────▼─────────┐
      │ Remote Domain A│     │ Remote Domain B │      │ Shared Platform│
      │                │     │                 │      │ UI / Utilities │
      └───────┬────────┘     └────────┬────────┘      └──────┬─────────┘
              │                       │                       │
              └───────────────────────┼───────────────────────┘
                                      │
                         ┌────────────▼─────────────┐
                         │     APIs / SDKs / Data   │
                         └──────────────────────────┘
```

### Architecture principles

1. **Boundaries before abstractions**
2. **Explicit contracts over implicit coupling**
3. **Local ownership over unnecessary global state**
4. **Shared code requires clear ownership**
5. **Measure before optimizing**
6. **Automate repetitive engineering work**
7. **Prefer reversible decisions**

## 🧩 Micro-Frontend

Micro-Frontend architecture is one of my primary areas of interest.

### Runtime model

```text
                         Host
                          │
          ┌───────────────┼───────────────┐
          │               │               │
     Authentication    Routing         Shell
          │               │               │
          └───────────────┼───────────────┘
                          │
              ┌───────────┼───────────┐
              ▼           ▼           ▼
           Remote A    Remote B    Remote C
              │           │           │
              └───────────┼───────────┘
                          ▼
                    Shared Platform
                          │
                    APIs / SDKs
```

### Key concerns

- Remote boundaries
- Shared dependency strategy
- React version compatibility
- Runtime failure isolation
- Contract testing
- Independent deployment
- Version compatibility
- Rollback strategy
- Observability
- Team ownership

### Dependency rule

```text
Host
 ├── Remote A       ✅
 ├── Remote B       ✅
 └── Shared         ✅

Remote A
 ├── Shared         ✅
 └── Remote B       ❌
```

The objective is to prevent accidental coupling between independently
owned applications.

## 🧠 System Design

I approach frontend system design through several layers:

```text
1. Product Requirements
          ↓
2. Domain Boundaries
          ↓
3. Runtime Architecture
          ↓
4. Data Flow
          ↓
5. Reliability
          ↓
6. Performance
          ↓
7. Delivery Strategy
          ↓
8. Observability
```

### Questions I consider

**Requirements**

- What problem are we solving?
- What are the critical user journeys?

**Boundaries**

- Which team owns each capability?
- Where should the application boundary exist?

**Data**

- Where does state live?
- Who owns the source of truth?

**Reliability**

- What happens when a dependency fails?
- Can a remote application fail independently?

**Performance**

- What is the critical rendering path?
- Which resources block interaction?

**Delivery**

- Can teams deploy independently?
- How do we rollback safely?

**Observability**

- How do we detect failures?
- How do we measure real user experience?
